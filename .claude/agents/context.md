## Conventions

### File and component naming
- Feature components use **PascalCase** filenames: `ChatWindow.tsx`, `HeroSection.tsx`, `ProjectsSection.tsx`
- Hook files use **camelCase** with `use` prefix: `useWebLLM.ts`, `useCarouselNavigation.ts`
- Content/data files use **camelCase**: `content.ts`, `data.ts`
- Type definition files: `types.ts` (co-located with the feature)
- Utility/lib files: `lib/<name>.ts` inside feature or shared
- Test files mirror the source filename: `ChatBubble.test.tsx`, `project.test.ts`
- Each feature folder has an `index.ts` barrel file for its public exports

### Feature directory pattern
```
src/features/<feature>/
  components/     — presentational components
  hooks/          — custom hooks
  workers/        — Web Workers (chat feature only)
  lib/            — pure utility functions
  content.ts      — all static copy and data for the feature
  data.ts         — structured data records (projects feature)
  types.ts        — TypeScript interfaces/types
  index.ts        — barrel export
```

### Module / import style
- **ESM throughout** (`"module": "esnext"` in tsconfig)
- **Path alias:** `@/*` maps to `./src/*` (configured in both `tsconfig.json` and `vitest.config.ts`)
- Cross-feature imports use the alias: `import { heroContent } from '@/features/home/content'`
- Within-feature imports use relative paths: `import { buildSystemPrompt } from '../content'`
- Node built-in test runner imports use explicit `.ts` extension: `import { projects } from './data.ts'`

## Constraints

### Observed from source files

- **No server-side data fetching or API routes.** All portfolio content lives in static TypeScript modules (`content.ts`, `data.ts`). Do not introduce API routes or server actions for content that is already static.

- **AI chat is WebGPU-only and client-side only.** The `useWebLLM` hook gates on `'gpu' in navigator`. The feature must remain fully client-side — no server inference, no API keys. The worker file (`llm-worker.ts`) must stay as a Web Worker entry point.

- **Model is fixed at `Qwen2.5-0.5B-Instruct-q4f16_1-MLC`.** The `MODEL_ID` constant and `localStorage` cache key are tied to this string. Changing the model requires updating both and clearing user cache.

- **`isRenderableExternalUrl` must be used before rendering any external link** from project data. It guards against `javascript:` URIs, `mailto:` links, and placeholder strings like `REPLACE_WITH_URL`.

- **`'use client'` directive required on all interactive components.** Next.js App Router defaults to server components; any component using hooks, browser APIs, or event handlers must have `'use client'` as its first line.

- **Turbopack is used for both dev and build.** Do not add webpack-specific plugins or config. The `next.config.ts` is intentionally minimal.

- **Tailwind v4 CSS-first approach.** There is no `tailwind.config.js`. Custom design tokens (`foreground`, `background`, `surface`, etc.) and animation classes (`animate-enter`) are defined in the CSS layer. Do not create a JS config file.

- **Two test runners must be kept separate.** `.test.ts` files (no `x`) use Node built-in runner. `.test.tsx` files use Vitest. Mixing them will break the test commands.

- **Path alias `@/*` must be used for cross-feature imports.** Relative `../../` traversal across feature boundaries is not the pattern used in this codebase.

- **No formatter is configured.** Unknown — needs human input. Formatting style should be agreed before any large-scale edits to avoid noisy diffs.

- **No Node.js version is pinned.** Unknown — needs human input. Add `.nvmrc` or `engines` field if this becomes a team project.
